# `aw build --force` optimization record (2026-11-03)

Branch: `perf/build-force-2026-11-03`, base `main` @ `6dbe57a`.
Final commit: `968e160` (`fix(parse): add Default for ParserSlot`).
Binary: `aw 0.2.1`, schema v7. Baseline binary: `main` @ `6dbe57a`,
`sha256 d9afa1b1993f91625b8bcef186a3aa0901001e6cda43370591eaec18f0c362c4`.

Host: macOS 27.0.0 arm64, 8 CPU, 16 GB. The host was **not quiet** during the
final measurement (external benchmark activity; load average 41.66-53.89,
8 CPUs). The primary performance evidence below is therefore the interleaved
A/B comparison, not the absolute wall time. The best absolute run still met the
2.91 s budget under that load.

Corpus: `/tmp/aw-bench/corpus`, generated by
`python3 -I tests/scripts/make_synth_corpus.py /tmp/aw-bench/corpus --files 2025`.
2,025 files, 11,208,525 bytes, 85,050 symbols, 164,025 edges.

## Result

Best-of-7 interleaved A/B, one baseline run and one final run per round:

| metric | baseline `6dbe57a` | final `968e160` | delta |
|---|---:|---:|---:|
| wall, best-of-7 | 3.61 s | **1.87 s** | -48.2% |
| wall, median | 4.04 s | **1.99 s** | -50.7% |
| `parse=` median | 1.39 s | 0.93 s | -33.1% |
| `db=` median | 2.37 s | 0.96 s | -59.5% |
| derived `resolve` median | 0.22 s | 0.10 s | -54.5% |
| index size | 69,103,616 B | 66,404,352 B | -3.9% |
| peak RSS | 155,370,048 B | 194,839,104 B | +25.4% |

`resolve` is derived as `wall - walk - parse - db`; the build does not print a
resolve field (output contract unchanged).

Peak RSS rose by about 40 MB. The likely contributors are the 32 MB SQLite
build page cache (`cache_size=-32768`) and allocator retention during FTS text
construction. This is inside the planned 50 MB guard, but the design-doc
<100 MB target predates schema v5 (the schema-v5 baseline was already 183 MB).
If RSS is a hard constraint, reduce `cache_size` and re-measure.

The final best run (1.87 s) is below the 2.91 s budget and below the handoff's
quiet-host baseline (2.70-2.79 s) even though the host was heavily loaded. A
quiet-host re-measure is still recommended to publish an absolute number.

## Durability smoke (`journal_mode=OFF`)

A build was SIGKILLed as soon as `.aw/index.db.new` appeared (during the DB
phase). Result:

- The orphan `.new` was 57,344 bytes.
- The published `.aw/index.db` still answered `aw stats` with the full
  2,025-file / 85,050-symbol / 164,025-edge totals.
- The next `aw build --force` removed the orphan and completed in 1.87 s.

The build connection writes only the disposable `.new` with
`journal_mode=OFF`/`synchronous=OFF`. `publish_new_index` closes the connection
(pager flush), fsyncs the file, then renames it onto `index.db` (best-effort
directory fsync). A crash before the rename leaves the previous index intact;
the build lock removes the orphan on the next build.

## Reproduction

```bash
python3 -I tests/scripts/make_synth_corpus.py /tmp/aw-bench/corpus --files 2025
cargo build --locked --release

# interleaved A/B, one run of each per round
for i in $(seq 1 7); do
  /tmp/aw-bench/aw-baseline --root /tmp/aw-bench/corpus build --force
  target/release/aw --root /tmp/aw-bench/corpus build --force
done
```

Canonical dumps used the tables and `ORDER BY` clauses in
`tests/cli.rs::parallel_builds_produce_identical_tables` plus
`clone_groups`, `symbols_fts`, `meta`, and `sqlite_master`.

## Limitations

- The host was loaded (41.66-53.89); absolute wall numbers are inflated. The
  interleaved best/median deltas are the robust result. Re-run best-of-7 on a
  quiet host before publishing a headline absolute number.
- The 2,025-file corpus is Python-only and uniform. Rust and TypeScript
  coverage comes from the self-index and a small TS fixture corpus; no large
  real-world multi-language corpus was available on this host.
- B3 (parser reuse) is logically sound and removes per-file parser
  construction, but its isolated wall delta could not be separated from host
  noise. It is kept because row parity and all tests pass; the quiet-host A/B
  can confirm the size of the win.
