1. Luận điểm Cốt lõi & Chỉ số Thực nghiệm (Executive Rollup)

EVIDENCE: docs/EVALUATION.md • skills/aw-first/SKILL.md

Kết luận trực diện: Mức tiết kiệm token của agent-weave (aw) là có thật (-27,3% input tokens ở pha điều hướng) nhưng hoàn toàn không tự động. Nếu chỉ gắn MCP hoặc CLI cho Coding Agent mà không nạp kèm chính sách định tuyến bắt buộc (skills/aw-first/SKILL.md), số lượt gọi tool của agent bị đội lên +73,3% và mức giảm input token gần như bằng không (-2,8%).

Khi quy đổi ra toàn bộ vòng đời một phiên làm việc thực tế của Coding Agent (bao gồm đọc thân hàm, viết code/diff, chạy test và cập nhật lại index), aw giúp giảm ròng khoảng 5,7% tổng lượng token ở 30% nav share (tối đa ~8% ở 40%) theo mô hình ước tính. Công cụ phát huy giá trị cao nhất ở bài toán truy vết chuỗi gọi hàm sâu (aw path, aw callers) trên monorepo tĩnh, nhưng không có lợi thế ổn định hoặc có thể làm tăng token cục bộ đối với các tác vụ tìm kiếm ngữ nghĩa, đọc file nhỏ hoặc kiểm toán code.

2. Đánh giá Cách trình bày & Kiến trúc Tính năng Kỹ thuật

SOURCE: README.md • AGENTS.md • Cargo.toml • src/mcp.rs

Điểm sáng trong Cách trình bày (README.md & EVALUATION.md)

  • FACT Chống thổi phồng (Anti-Hype Documentation): Ngay trang đầu của README.md đặt mục "Know what the answer does not prove", khẳng định rõ kết quả rỗng không chứng minh hàm không được gọi ở runtime.
  • FACT Tự bạch sai số thực nghiệm: Mục mở đầu docs/EVALUATION.md công khai đính chính việc phiên bản tài liệu cũ gộp chung kết quả của nhiều schema khác nhau và nhầm lẫn giữa Mean Query Recall (0.775) với Pooled Recall (0.786).
  • DECISION Tách biệt 3 tầng tích hợp: Trong docs/agent-integration.md, tác giả phân định rạch ròi giữa CLI (thực thi lệnh), MCP Server (cung cấp schema qua stdio) và Skill aw-first (luật định tuyến và hợp đồng tin cậy).
"These are workflow differences, not a promise of complete coverage or universal savings. Existing editor references, language servers, and grep may already answer a small question efficiently." — Trích README.md (dòng 24–27)

Kiến trúc Kỹ thuật & Kỷ luật An toàn (AGENTS.md & src/mcp.rs)

  • FACT Zero-Daemon, Zero-Network, Zero-Unsafe: Binary viết bằng Rust đồng bộ (Cargo.toml chỉ dùng clap, tree-sitter, rusqlite bundled, ignore, serde_json). Tốc độ build ~2.025 files (85.050 symbols) đạt 1,87 – 1,99 giây (best/median dưới load average 41,66–53,89; cần đo lại trên host yên tĩnh).
  • FACT Cơ chế Cô lập Ghi đĩa (Write Confinement): Mọi thao tác ghi chỉ diễn ra trong thư mục .aw/ và bị kiểm soát tự động bởi script tests/scripts/write_path_check.sh.
  • DECISION Cắt tỉa bề mặt MCP mặc định: Trong src/mcp.rs (dòng 19–21), hằng số CORE_TOOLS chỉ phơi bày 8 công cụ điều hướng cốt lõi thay vì toàn bộ 21 MCP tool, ngăn chặn việc làm tràn ngữ cảnh của agent bằng các công cụ kiểm toán nhiễu.
"enforce query-first routing strictly on proven high-ROI graph commands (build, path, context, callers, callees, impact, imports); keep noisy or human-audit commands (tests, dead, complexity, hotspots, report, stats, files) out of mandatory agent routing." — Trích AGENTS.md (dòng 48–50)

3. Phản biện Red-Team: Kiểm chứng Lời hứa Tiết kiệm Token (CLAIM → EXTRACT → DOUBT → RECONCILE)

METHOD: Critic-Review • Doubt-Driven Development
Bước 1 & 2 (CLAIM & EXTRACT): Bóc tách Giả thuyết Cốt lõi và Hợp đồng Kinh tế học Token Core Contract

CLAIM (Giả thuyết của dự án)

Xây dựng đồ thị tĩnh cục bộ (.aw/index.db) giúp Coding Agent trả lời ngay các câu hỏi về quan hệ gọi hàm và phụ thuộc bằng danh sách tọa độ path:line, từ đó tránh phải chạy grep lặp đi lặp lại và đọc toàn bộ nội dung nhiều file không liên quan.

CONTRACT (Điều kiện bắt buộc để tiết kiệm Token thật)

Phương trình tiết kiệm ròng: Token_Saved(Bớt đọc file + Bớt bước mò đường) > Token_Cost(MCP Schema + Skill Prompt + Lệnh aw + Fallback khi aw mù + Rebuild sau khi sửa code).

Bước 3 (DOUBT): 5 Phản biện sắc lạnh bóc trần giới hạn thực tế của aw 5 Điểm nghẽn Thực chứng
  1. Thuế "Gọi Kép" khi thiếu Kỹ luật Định tuyến (The Double-Verification Tax): Trong thực nghiệm tại docs/EVALUATION.md (Mục 2), khi agent được cấp aw nhưng không bị khóa bởi Trust Contract, agent xem aw như một gợi ý phụ: nó gọi aw (3,7 lần/run) rồi vẫn gọi thêm grep và đọc file để tự kiểm chứng, đẩy tổng số tool calls từ 20,6 lên 35,7 lượt (+73,3%).
  2. Độ mù Phân giải Tĩnh 51,8% – 90,4% đẩy Agent vào bẫy Fallback tốn kém gấp đôi: Theo src/extract/resolve.rs (dòng 676–805), bộ phân giải chỉ nối được cạnh khi gọi trực tiếp theo tên module, self/cls/this trong thân lớp, hoặc biến cục bộ được gán trực tiếp từ constructor (obj = Class()). Mọi lời gọi qua Dependency Injection, callback, higher-order function, dynamic dispatch, hoặc phương thức trả về từ hàm factory (như lỗi C4 trong review-findings.md) đều rơi vào Outcome::Unresolved. Khi 1 cạnh giữa đường bị đứt, aw path A B báo không có đường đi; agent vừa mất token gọi aw, vừa phải quay lại chạy grep từ đầu.
  3. Ngụy biện "Chỉ đếm pha Điều hướng" (Navigation-Only Benchmark Bias): Con số -27,3% input tokens được đo trên 5 bài tập chỉ yêu cầu liệt kê danh sách điểm gọi. Trong thực tế, Coding Agent không chỉ liệt kê tọa độ mà phải đọc thân hàm để hiểu logic và sửa code. Vì bảng symbols trong schema.sql (dòng 43–45) chỉ lưu tối đa 160 ký tự dòng chữ ký đầu tiên (signature) và không lưu thân hàm, agent bắt buộc phải dùng view_file / read_file để đọc mã nguồn trước khi sửa.
  4. Chi phí Ngữ cảnh Cố định (Fixed System Prompt Overhead) và Chi phí Rebuild: Nạp 8 tool schemas từ src/mcp.rs cùng nội dung skills/aw-first/SKILL.md tiêu tốn khoảng 1.200 – 1.800 input tokens trên mỗi lượt gọi model (tương đương 24.000 – 36.000 cached/uncached input tokens cho một phiên 20 turns). Hơn nữa, mỗi khi agent sửa 1 file, index lập tức bị cũ (stale) và agent phải tốn thêm 1 lượt gọi tool aw build trước khi truy vấn tiếp.
  5. Sự phụ thuộc nặng nề vào Host/Model và Nhiễu từ các Lệnh Phụ: Trong docs/EVALUATION.md (Mục 3), cùng một tính năng search giúp giảm 28% token trên Grok trong retest signature/delegation (identifier lookup chỉ +0,2%) nhưng lại làm tăng +10% token trên zcode; lệnh tests làm tăng +89% tool calls trên agy; lệnh API inventory làm tăng +14% đến +125% tool calls trên cả 3 host.

6. Kết luận Thẳng thắn & Cấu hình Thực chiến cho Coding Agent

DECISION MATRIX

Khi nào aw CHẲNG CÓ GIÁ TRỊ GÌ (Nên tắt hẳn)?

  • Repository nhỏ (< 100 files) hoặc làm việc cục bộ trên 1–2 file đã biết: ripgrep (rg) + đọc file trực tiếp luôn nhanh hơn và tốn ít lượt gọi model hơn.
  • Codebase nặng tính động (Dynamic/Metaprogramming): Dự án dùng nhiều Jupyter Notebooks (độ phủ chỉ 10%–19%), Python monkey-patching/decorators phức tạp, hoặc chuỗi callback ẩn danh.
  • Tác vụ viết tính năng mới thuần túy hoặc sửa lỗi UI/CSS/SQL: Nơi nút cổ chai nằm ở việc đọc hiểu tài liệu/logic nghiệp vụ và chạy trình biên dịch/test chứ không phải tìm ai gọi hàm nào.
  • Agent Host không hỗ trợ nạp Skill / System Instructions tùy chỉnh: Nếu chỉ cắm được MCP Server mà không ép được luật aw-first, bật aw sẽ làm agent tốn thêm 73% lượt gọi tool.

Khi nào aw THỰC SỰ ĐÁNG GIÁ & Cách dùng Tối ưu?

  • Monorepo / Backend quy mô vừa và lớn (500 – 10.000+ files) bằng Rust, TypeScript hoặc Python có Type Hint: Đặc biệt hiệu quả khi dò luồng thực thi xuyên tầng (aw path) hoặc kiểm tra tác động trước khi đổi chữ ký hàm (aw callers, aw context, aw impact).
  • Mẹo tối ưu hóa Token cao nhất (Bỏ qua MCP, dùng CLI + Skill): Thay vì chạy aw mcp (tốn ~1.000 tokens JSON schema ở mọi turn), chỉ cần cài binary aw vào PATH và nạp skills/aw-first/SKILL.md để agent gọi trực tiếp aw path / aw callers qua công cụ Bash sẵn có.
  • Chỉ giữ đúng 7 lệnh trong Routing: build, path, context, callers, callees, impact, imports. Bỏ qua toàn bộ các lệnh kiểm toán (dead, clones, tests, complexity, hotspots) đối với Coding Agent.
