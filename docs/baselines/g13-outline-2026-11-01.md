## T4/T5 scores — pre-existing contract drift, NOT an F1 regression

Both arms score T4 recall 0% / T5 precision 56% (recall-only mode, not
gating), with IDENTICAL miss/extra sets. Root cause, verified against the
frozen `expected/T4.json`: the frozen set stores CALL-SITE lines for the
parser-internal stage methods (`hierarchical_parser.py:102,121,137,...`) plus
the wiring row `pipeline.py:40`, while the current `callees` contract emits
DEF-line pointers (`:110,220,249,...` — def lines confirmed by the outline
output itself). The G6 kg arm scored 100% because the P1-era binary still
emitted call-site rows for same-file callees; the contract has since moved to
def-line semantics (documented in the G6 answer's own note: "kg closure
pointers use def-line semantics (callees contract)"). The mismatch affects
both current-binary arms equally — it is pre-existing and orthogonal to F1.
