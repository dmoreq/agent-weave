## Critical

C1 — F4/F8 miss the stated 1M-edge budget by 6.7-7.6x on a hub-shaped
cross-file corpus. `impact --depth 3` 1,132.5 ms vs 150 ms; `tests` hub 1,335.6
ms vs 200 ms; at 3.1M edges 2,762.9 ms and 3,256.0 ms. `--limit 5` does not
reduce impact cost. Root: full inbound ORDER BY and 500-id BFS chunks. The
corpus is adversarial; no realistic 1M-edge repo was available.

## Important

1. Build overhead is exactly at the 1.25x gate: P8 2.58-2.65 s vs v5 2.05-2.13 s;
   best/best 1.259x, median paired 1.251x. Frozen absolute budget 2.91 s passes.
2. 987k-symbol build is 82 s, unbudgeted (23,500 files, 1.9M edges).
3. `dead` has no >85k budget: 716.7 ms @1.37M edges, 1.50 s @3.1M.
4. `api` scans the whole symbol table; 305 ms directory @987k, no 1M budget.
5. `files`/`symbols` are cardinality-bound; 170.8 ms symbols @987k.

## Suggestions

- F9 path-scoped complexity has only 10-24% headroom.
- F11 has no generated-file timing corpus.
- Best-of-7 hides tails; report median/p95 for scale-sensitive gates.
- `implementers` is process-floor-bound; no large inheritance corpus.

## Caveats

Host load ranged 3.3-13.3; loaded runs 30-40% worse. Synthetic hub is
adversarial. All indexes rebuilt by the frozen binary; query API/context/stats
have no 1M-edge budgets.
