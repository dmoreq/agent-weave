## 1. Method

1. Parsed all 80 rows of `metrics-p8.jsonl` (5 tasks x 2 arms x 4 hosts x 2 runs).
2. Scored all 79 captured answers with the frozen scorer, imported as a module:
   `score_p8.py:30 score_answer` with `score_p8.py:20 norm`. 75 OK, 4 FAIL.
3. Applied the validity rule: a cell is valid when `host != opencode` and no
   violation contains `control arm called`. This reproduces the documented
   58/60 valid-host cells.
4. Recomputed medians per `(task, host, arm)`. With n=2 the median equals the
   mean of the two runs; with n=1 it is the single value.
5. Token metrics are reported two ways because the protocol records them
   separately: `in+out`, and full context `in + cache_read + out`. The
   `cache_read` component is visible only inside the context figure.
   Tokens are never pooled across hosts, per `protocol.md:84`.

Metric fields used: `tools`, `tok_in`, `tok_out`, `cache_read`, `correct`,
`violations`, `host`, `arm`, `task`, `run`. Reproduction command in section 9.

No feature reaches (b), because no feature reaches (a) and therefore no KEEP

Sensitivity, rejected: pooled across hosts, D1 is n=6 per arm and its pooled

## 7. Findings

### Critical

**C1. Every valid treatment cell paid a failed mandatory first command.**
`grep -l "no git root ancestor" docs/baselines/p8-utility-2026-11-03/logs/*.jsonl`
returns 33 files. Parsing each host's transcript gives 30/30 valid treatment
cells with the error and 1/28 valid control cells (`agy-kgc-r2-H1`).

Evidence:
- `logs/zcode-kgp8-r1-A1.jsonl`: first tool result `Exit code 2 / kg: usage: no git root ancestor found - pass --root <path>`; retry with `--root` succeeds.
- `logs/grok-kgp8-r1-D1.jsonl`: step 7 `exit: 2 ... no git root ancestor found`; step 11 succeeds with `--root /private/tmp/.../vihap`.
- `logs/agy-kgp8-r1-A1.jsonl`: `Command exited with code 2`; retry `kg --root . api ...` succeeds.
- Source: `src/walk.rs:53` raises the usage error when no git root ancestor exists. The sanitized corpora under `/private/tmp/p8-utility-corpus-2026-11-03/` are not git repositories.

Effect: every treatment cell carries at least one failed tool call before the
feature output. The measured treatment tool counts are therefore upper bounds,
and the measured savings are lower bounds. This does not create a KEEP. It
weakens any DEMOTE or REMOVE case for F8/F10, because their negative deltas
include this fixed handicap; it does not by itself overturn them. It also
makes the published statement "No treatment cell failed because of a kg output
defect" (`p8-utility-2026-11-03.md:65`) true only at the answer level; the
mandated command failed in 100% of treatment cells.

Related: `feature_calls` counts failed invocations. `agy-kgp8-r1-A1` records
`kg_tools {"api": 2}` where the first `api` call exited 2. The
"treatment must call the feature" check (`run_p8.py:403-406`) can therefore
pass on failed calls alone, and does here. The same metric is not comparable
across hosts: for grok, `transcript_kg_calls` is 0 (the gated session files
were not parsed), so `kg_calls`/`feature_calls` come from the usage journal and
exclude the failed attempt; for agy and zcode they include it. Example:
`grok-kgp8-r1-D1` has `journal_calls=1, transcript_kg_calls=0`, while
`zcode-kgp8-r1-D1` has `transcript_kg_calls=3`.

### Important

**I1. The published agy control means are still wrong in the table body.**
`p8-utility-2026-11-03.md:53` shows 19.0 and line 55 shows 21.0. Raw valid
control values are 18 (I1 r2) and 18 (H1 r2); the contaminated r1 runs are 24
and 24. The H1 row is internally inconsistent: 21.0 -> 7.0 is -66.7%, but the
row prints -61%, which is the 18.0 -> 7.0 value. The limits doc asserts a
correction that is not present in the table.

**I2. The battery verdicts are not transferable to R14.**
`p8-utility-2026-11-03.md:51-57` applies a 20% mean rule on 3 valid hosts.
R14 applies 25% median with n>=5 (`README.md:16`). The battery's D1 `KEEP`
label therefore cannot be cited as an R14 KEEP. This is the main reason the
headline published result overstates the evidence.

**I3. A retained control cell used a P8 F1 surface and an unlisted command.**
`agy-kgc-r2-H1` has `kg_tools {"symbols": 2, "context": 2, "search": 2, "dead": 1}`.
`kg dead` is an F1 surface (`R13-p8/evidence/features/F1.md`), and neither
`dead` nor `context` is in the protocol's allowed control set
(`protocol.md:13-14`: callers, callees, symbols, search). The runner did not
flag it because the violation check only inspects the pinned feature name
(`run_p8.py:403-406`). H1's only agy control number (n=1) is therefore
partially F1-equipped, so the -61.1% agy H1 delta is not a clean control.

**I4. The feature caveat line triggers redundant verification and compresses
every treatment saving.** The treatment sequences show the pattern: `kg`
returns the exact answer, then the agent greps and reads to resolve the caveat.
- `grok-kgp8-r1-D1` reasoning: "The 'unresolved imports omitted' warning
  creates ambiguity about whether `kg impact` missed any direct importers. A
  targeted grep ... will resolve this." The cell then spends 3 reads, 1 grep,
  and 1 write after a correct 3-row `impact` output.
- `agy-kgp8-r1-T1`: `kg tests` returns the direct test in one row, then the
  agent spends 7 calls on reads and greps.
- `zcode-kgp8-r1-A1`: `kg api` returns all 15 interfaces, then the agent greps
  the file.
This is a product trust defect, not evidence of feature uselessness. It is the
main reason A1 and T1 show cost increases.

**I5. Host and model are fully confounded.**
`metrics-p8.jsonl` `model` values: grok `grok-4.7-build`, agy
`gemini-3.8-flash-high`, zcode `deepseek-ai/DeepSeek-V4.1-Flash-1017`.
Every host-host delta is also a model delta. Host-level deltas (e.g. agy 20.5
vs zcode 10.0 control tools on D1) cannot be attributed to the harness.

**I6. Token and tool deltas disagree in sign for F4 on grok.**
D1 grok: tools -29.4%, tokens +1.9%. Per `protocol.md:84`, tokens are not
pooled and `cache_read` is host-specific (grok reports 0 by construction).
A KEEP or IMPROVE claim that uses "tool-call or token" must state which metric
passed. For F4, tools pass on 3/3 hosts; tokens pass on 2/3.

### Suggestion

**S1.** Replace the free-text caveat line with a scope line plus a stable
confidence marker, or add a `--quiet` mode, so agents do not spend calls
re-checking an exact answer. Cite `grok-kgp8-r1-D1` step 17 reasoning.

**S2.** Let `kg` fall back to `cwd` when no git ancestor exists and a `.kg/`
index is present, or print an actionable `--root <cwd>` recommendation in the
error. This removes 1 failed call per agent session in non-git corpora
(`src/walk.rs:53`).

**S3.** Count successful feature invocations separately from failed ones
(`run_p8.py:384-396`). The current `feature_calls` merges both.

**S4.** Record per cell how the root was resolved (git ancestor, `--root`,
cwd). This makes root-mode a covariate instead of a hidden handicap.

**S5.** Pre-register either n=5 per `(task, host)` or a pooled estimand with
host as a blocking factor before the next battery. Do not choose after seeing
results.

**S6.** Add per-cell token medians (`in+out`, `cache`) to the published table,
not only means of `tok_in`.

**S7.** Enforce the full allowed-command set on control cells, not only the
pinned feature. At minimum, flag `kg dead`, `kg context`, and any other
non-legacy subcommand (`run_p8.py:403-406`).

## 8. Evidence gaps that block a defensible decision

1. Six of eleven features (F2, F3, F5, F6, F9, F11) have no utility task. Their
   decisions are DEFER by construction.
2. No feature has n>=5 per cell. The R14 KEEP bar cannot be met by any cell.
3. F4 has no depth>1, calls, inherits, `--explain`, or `--context` shape.
4. F8 has no transitive shape. T1 asks for a direct caller, which is the
   weakest use of a depth-10 reverse BFS.
5. F10 has no directory or multi-file shape and no Python `__all__` or Rust
   `pub` shape. A1 is a 176-line file.
6. F1 has no `dead` shape; H1's agy control is n=1 and F1-contaminated.
7. No clean baseline where the mandated command succeeds on the first call.
8. Tokens mix cache and non-cache across hosts; grok cache is 0 by
   construction, so token comparisons are not like-for-like across hosts.

```sh

python3 -I - <<'PY'
import json, statistics, importlib.util
from pathlib import Path

here = Path('.')
spec = importlib.util.spec_from_file_location("sp8", here / "score_p8.py")
sp8 = importlib.util.module_from_spec(spec); spec.loader.exec_module(sp8)

rows = [json.loads(line) for line in open('metrics-p8.jsonl')]
for row in rows:
    answer = here / 'answers' / f"{row['runid']}.json"
    row['ok'] = sp8.score_answer(row['task'], answer)[0] if answer.exists() else None
    row['valid'] = (row['host'] != 'opencode'
                    and not any('control arm called' in v for v in row['violations']))

def med(values):
    return statistics.median(values) if values else None

def pct(new, old):
    return f"{(new - old) / old * 100:+.1f}%"

groups = {}
for row in rows:
    groups.setdefault((row['task'], row['host'], row['arm']), []).append(row)

for task in ('I1', 'T1', 'H1', 'D1', 'A1'):
    for host in ('grok', 'agy', 'zcode'):
        control = [r for r in groups[(task, host, 'kgc')] if r['valid']]
        treat = [r for r in groups[(task, host, 'kgp8')] if r['valid']]
        if not control or not treat:
            continue
        cross = med([r['tools'] for r in control])
        treate = med([r['tools'] for r in treat])
        coin = med([r['tok_in'] + r['tok_out'] for r in control])
        toin = med([r['tok_in'] + r['tok_out'] for r in treat])
        ctxc = med([r['tok_in'] + r['cache_read'] + r['tok_out'] for r in control])
        ctxt = med([r['tok_in'] + r['cache_read'] + r['tok_out'] for r in treat])
        print(task, host, f"{len(control)}/{len(treat)}",
              f"tools {cross}->{treate} {pct(treate, cross)}",
              f"tok {coin}->{toin} {pct(toin, coin)}",
              f"ctx {ctxc}->{ctxt} {pct(ctxt, ctxc)}",
              f"correct {sum(1 for r in control if r['ok'])}/{sum(1 for r in treat if r['ok'])}")
PY
```
