## Findings

### Critical

None. No feature failed its re-derived GT or fixture set, and no claim that
drives a KEEP decision was contradicted by source.

### Important

I1. `docs/baselines/dead-precision-2026-11-03.md` is not reproducible.

- Stated method: "count textual occurrences of its bare name in every `.py`
  file except the definition line"; stated result "0/50".
- Reproduction on the same corpus state (`files=252 symbols=3291 edges=11294
  unresolved=4984`) with `dead --exclude-tests --limit 50` (deterministic, two
  runs identical) and a Python `ast` oracle at the emitted line:
  `candidates=50 parsed=50 zero_external=6 one=11 many=33`.
- Zero-reference candidates: `scripts/overengineering_metrics.py:108
  FunctionInfo`, `vihap/grammar/admin.py:692
  compile_anchored_prefix_alternation`, `vihap/grammar/entity.py:235
  acronyms_in_text`, `vihap/grammar/entity.py:245 landmarks_in_text`,
  `vihap/grammar/hamlet.py:343 compile_hamlet_digit_pattern`,
  `vihap/grammar/landmark.py:436 swap_bilingual_admin_spacing` — each appears
  exactly once in the corpus (its definition).
- Impact: the probe's conclusion direction is unaffected (dead is still a
  low-precision candidate generator), but the headline number and
  `remediation.md`'s restatement are wrong. L6 should verify the oracle and
  either check it in or correct the doc.

I2. Ambiguous call sites are invisible in `impact` and `unresolved`.

- Fixture `pkg/redef.py` redefines `dup` twice and calls it from
  `user_of_dup`. `kg callers dup` prints two candidates and exits 2;
  `kg impact pkg/redef.py --sites` prints `no-results: 0 impacting files
  found`; `kg unresolved --names --path pkg/redef.py` prints `no-results: 0
  unresolved names`.
- Source: `src/query.rs` impact site SQL joins `symbols ds ON ds.id =
  e.dst_id` and `files df ON df.id = ds.file_id`, so `AMBIGUOUS` edges (NULL
  `dst_id`) can never match a target path; the `[ambiguous]` tag branch in
  `impact` is dead code.
- The R13 F2/F4 sheets document the unreachable tag, but the user-facing
  caveats say only "resolved static edges only; dynamic dispatch may hide
  dependents". A caller file with an ambiguous call into the target is
  neither dynamic dispatch nor reported.

I3. `api` silently omits exported non-callable declarations.

- `kg api packages/core-ledger/src/types.ts` returns the 15 exported
  interfaces and omits the 8 exported type aliases on lines 1, 15, 32, 33,
  50, 88, 138, 176 (`AccountType`, `PostingDirection`, `TransactionStatus`,
  `TransactionSource`, `CategoryType`, `AuditAction`, `Command`, `Result`).
- Rust `pub const LIMIT`, `pub static GLOBAL`, `pub type Alias` are absent
  from both `symbols` and `api` (`rust/items.rs` fixture).
- Source anchor: `src/query.rs:2109` filters
  `s.kind IN ('function','method','class','trait','interface')`; the
  extractor creates no symbol for const/static/type alias/variable.
- The output caveat mentions re-exports, module visibility, and dynamic
  exports, but not non-callable exports. The F10 question "public API/export
  surface" is therefore answered incompletely and silently. A1 does not
  cover this because its oracle is "15 exported interfaces".

I4. Committed GT counts and the claims that cite them disagree.

- `docs/baselines/inheritance-gt.jsonl` has 17 rows (15 vihap, 2 finguard).
- `README.md` line 25 still says "P8 real-corpus GT 71/71 (imports 40/40,
  tests 20/20, inheritance 11/11)"; `docs/baselines/reviews/R13-p8/evidence/
  features/F1.md` says "11 rows: 10 vihap Python, 1 finguard TS".
- `remediation.md` says 17 rows / 17/17; the README total should be 77, not
  71. The committed GT, the R13 sheet, and the README cannot all be current.

I5. "17/17 inheritance recall" is not independently reproducible here.

- `tests/scripts/inheritance_recall.py` with the available finguard subset
  (`/tmp/p8-utility-corpus-2026-11-03/finguard`, 77 files) reports 15/17. The
  vihap subset is 15/15; the `Preferences` finguard row verifies on the
  subset (`apps/web/src/providers/preferences-context.ts:14`), but the
  `SnapshotStore → MemorySnapshotStore` row cannot be checked because the
  subset has no `packages/db`. A full finguard corpus at revision `dddfe07`
  is required to sustain "17/17".

### Suggestion

S1. Latency numbers drift between documents: `docs/baselines/p8-latency-
2026-11-03.md` 112.2/163.4 ms, `remediation.md` 117.1/162.6 ms, my rerun
110.1/166.3 ms (`timing_assert.sh 7` on `/tmp/kg-r13-l3/edges1m-sub`). All
pass the 150/200 ms budgets; pin one table and cite the rerun.

S2. `impact --explain` alone does not print the static-edge caveat, while
`--context` does. `src/query.rs:1272` computes
`extended = depth > 1 || context || kinds.iter().any(...)`; `explain` is not
included, yet `explain` forces per-site rows. Add `explain` to `extended`.

S3. `unresolved` default and `--names` should label their scope in the
header: fixture default prints "unresolved=3 callees in 3 files, 2 distinct
names" while `--names` prints "6 rows (call/import/inherit)". The sheet calls
this byte-identical behaviour intentional; the header can still say
"call-only" without changing rows.

S4. Python non-literal `__all__` is discarded entirely
(`python_all_names` returns `None` for anything but a list/tuple of strings;
`extract.rs:536-575`), so `__all__ = [n for n in (...)]` falls back to the
underscore rule. Verified on `py/spec.py`: `a` exported, `_b` not, generator
in the `__all__` ignored. Consider one caveat line when a non-literal
`__all__` is present.

S5. `dead` lists exported/public entry points as candidates: `py/spec.py:4`
(`a` is in `__all__`), `rust/items.rs` would also list any uncalled `pub fn`.
The caveat says entry points are not proven absent; an export-aware filter
would cut a known false-positive class.

S6. `files` has no per-file "changed since build" marker; only the build-time
header. Verified with `pkg/after_build.py` created after build: absent from
`files`/`symbols`/`dead` with no stale warning. The header is honest but does
not tell which rows changed.

   (`SnapshotStore → MemorySnapshotStore`) is unverified.

   number above is for the older binary.

   the clear case).
4. No P8 utility task exists for F2, F3, F5, F6, F9, F11; F3's only number is
   G13 (n=1 per arm, binary `fe1fcc0`).
5. F1's dead-precision oracle is not checked in; my reimplementation gives a
   different result (I1). No method-level diff is possible from the doc.
6. F5's `site_line=0` omission path is source-verified only; no fixture
   triggers it.
7. F7 has no TS import GT; F10 has no real-corpus export GT beyond A1's
   `types.ts` interfaces.
8. F8's 2679/2679 "precision" is a name-shape check (`test_*`/`test[A-Z]`),
   not reachability or path-policy proof.

   its recall cost on a real corpus is unmeasured.
