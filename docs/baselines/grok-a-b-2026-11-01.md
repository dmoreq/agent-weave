reads only; kg: same + kg CLI), 2 runs per cell = 20 grok sessions, executed

invocations (transcript audit + no journal entries); kg arm made 37 journaled

## Findings (honest)

1. **The frozen G6 anchor (-50% tool calls, -67% bytes) did NOT reproduce
   with a free-running agent.** The kg-arm agent used kg as a SUPPLEMENT
   (3.7 kg calls inside 35.7 total), not a replacement: it spent more tool
   calls exploring and verifying. Tool-output bytes were flat. The -50%/
   -67% numbers were measured on a different agent host/model/epoch; naive
   transfer to "an agent with kg" is refuted by this run.
2. **What kg bought instead was correctness at flat cost**: gating recall
   98.6% vs 81.9% (+16.7 pts), a clean +50 pts on T2 in both runs (the
   re-export blind spot is exactly the resolution algorithm's design goal),
   and every T4/T5 success belonged to a kg run. Tokens were equal (the
   ~52K-token session bootstrap dominates and is arm-invariant).
3. Intra-arm variance is real at n=2: T4/T5 each split 1/2 within the kg arm
   (kg-r2-T4 thrashed: 73 tool calls, recall 0). Averages over 2 runs are
   not per-task guarantees.
4. Task-contract misses independent of arm: T1 `grouping` (0-1/9 dirs
   everywhere — agents did not emit the expected per-dir key format) and T2
   `ordering` (0% everywhere). These are protocol/format artifacts, not
   capability signals.
5. T2 kg precision dips (60% r1) came from kg INCLUDING test-file callers;
   the expected essence excludes tests but the frozen question does not say
   so (T1/T3 do). Contract wrinkle, not a kg defect.

## Query-first routing arm (kgq) — 2026-11-01, later same day

Same protocol, kg arm only, prompt adds a binding routing clause: "run kg
FIRST for who-calls/impact/callees/flow questions; grep only for what kg
cannot answer". 10 runs planned; `kgq-r2-T5` wedged (0-byte log, no answer
file, no live process) and is EXCLUDED — n=9. Prompts: `/tmp/oc-g6-grok/
prompts/kgq-*` (ephemeral), manifest `grok-a-b-2026-11-01/manifest_q.txt`.

| metric (mean/run) | baseline | kg (unrouted) | kgq (routed) |
|-------------------|----------|---------------|--------------|
| tool calls | 20.6 | 35.7 | 26.6 |
| kg calls | 0 | 3.8 | 9.1 |
| tool output KB | 87.5 | 90.7 | 69.3 |
| input tokens | 1,058,613 | 1,028,665 | **816,300 (-22.9% vs baseline)** |
| output tokens | 13,773 | 13,403 | 10,850 (-21.2%) |
| model calls | 20.2 | 19.9 | 17.2 (-14.9%) |

Recall (check.py): gating T1-T3 = 98.6% (identical to unrouted kg; T2 100%
both runs vs baseline 50%). T4 recall-only: BOTH kgq runs hit the stage
classes (100%/90.9%) vs 1/2 unrouted kg, 0/2 baseline. T1 `grouping` 1/9 in
both kgq runs (best across arms, still failing the key contract). Precision
on recall-only tasks drops (11-26%) — kg's exhaustive pointers (incl. test
callers) flow into the answer; not gating.

Verdict: the token lever is real. Routing converts the agent from
explore-then-verify to query-then-annotate: -23% input tokens, -21% output
tokens, -15% model calls, at unchanged gating recall and a T4 improvement.
Cost: more reliance on kg answers as-is (precision dips on non-gating
tasks), and one wedged run in 10 (grok-side hang, unrelated to kg).
