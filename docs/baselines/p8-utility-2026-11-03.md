# P8 Agent-Utility Battery — 2026-11-03

**TL;DR** — Only direct dependency impact cleared the pre-registered bar:
`kg impact --edges imports --depth 1` reduced agent tool calls 29-45% on all
three valid hosts with correctness parity. Imports and inheritance were
**PARTIAL**. Test reachability and API inventory showed **no measured
economics win** on these tasks. OpenCode cells are invalid because that host
ignored the corpus working directory; raw rows are retained for audit.

Baseline kg `6dbe57a`, schema v7. Protocol: `p8-utility-2026-11-03/protocol.md`.
Raw metrics: `p8-utility-2026-11-03/metrics-p8.jsonl`.

## 1. Design

- 5 tasks x 2 arms x 4 hosts x 2 runs = 80 cells.
- Arms: `kgc` control (target P8 command forbidden) vs `kgp8` treatment
  (target P8 command first). Same binary.
- Budget 25 tool calls; journals wiped/moved per cell; answers outside corpus.
- Decision rule frozen before valid cells: a task is KEEP when at least 3
  valid hosts show correctness parity and either >=20% fewer tool calls or a
  control-failure/treatment-success correctness swing. With OpenCode invalid,
  the valid-host threshold is 3/3, stricter than the original 3/4.
- n=2 per cell. Results are directional, not significance tests.

Tasks:

| task | corpus | treatment route |
|---|---|---|
| I1 | kg | `kg imports src/query.rs` |
| T1 | vihap | `kg tests vihap.cleaners.text_utils.exact_text_key` |

| D1 | vihap | `kg impact vihap/reform/temporal.py --edges imports --depth 1` |

## 4. Interpretation

### D1 — direct dependency impact is the clear winner

The task asked for direct importers of `vihap/reform/temporal.py`; expected
three files. On all three valid hosts the P8 route reduced total tool calls by
29-45% at equal correctness. This is the only feature/task that clears the bar
on every valid host.

### I1 — imports is promising, not uniform

Grok cut calls by 71%. zcode was flat: the control already found the three
`use crate::` lines cheaply. agy's one uncontaminated control/treatment pair
missed the 20% threshold at 19%. Verdict PARTIAL.

### H1 — implementers is host-dependent

Agy showed a 61% reduction; Grok was 18% below the bar; zcode flat. The
question is small enough that source grep is cheap on two hosts. PARTIAL.

### T1 — tests did not pay for itself

All hosts were correct, but treatment did not reduce tool calls; agy increased
them by 89%. For a single pinned test symbol, grep/read is already efficient.
NO VALUE for this task shape.

### A1 — API inventory also did not pay

The treatment command added calls rather than replacing exploration; agy
increased calls by 125%. Correctness was equal, but the economics were
negative. NO VALUE for this task shape.

## 5. Threats to validity

- n=2 per cell; means are descriptive. No significance testing.
- Cross-host token values are not pooled. Grok's session bootstrap dominates
  small cells; OpenCode values are excluded with the host.
- The tasks are intentionally narrow. A single-target test/API question may
  understate value on a larger package inventory or multi-symbol migration.
- Static P8 limits remain: cross-file Rust impls, TS `describe`/`it`
  callbacks, function-local imports, external/unresolved imports.
- OpenCode could not be measured under the required corpus isolation. Re-run
  only if its CLI exposes a reliable per-run workspace root.

## 6. Verdict

Keep the direct dependency-impact workflow as a measured agent win. Treat
imports and implementers as partial, host-dependent wins. Do not claim measured
tool-call savings for tests or API inventory in this task shape; they remain
correctness/navigation aids.
